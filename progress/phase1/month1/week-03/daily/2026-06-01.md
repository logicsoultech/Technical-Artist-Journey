## Core Concepts Covered

### 1. What is Lumen and How Does It Work?

Lumen is UE5's built-in dynamic Global Illumination (GI) and reflection system, designed to react in real-time to scene changes — shifting sun angles, emissive material changes, destructible geometry, etc.

**Hybrid tracing pipeline:**

| Stage | Description |
|---|---|
| Screen Tracing (Screen Space) | First pass — traces light based on what is currently visible on screen |
| Lumen Scene & Surface Cache | Builds a low-resolution internal representation of the world; objects are wrapped in Lumen Cards that capture and cache surface lighting data |
| Ray Bouncing | When a ray hits a surface, Lumen calculates its bounce using Surface Cache data to produce realistic indirect lighting |

---

### 2. Software Ray Tracing vs. Hardware Ray Tracing

| Parameter | Software RT (SDF-based) | Hardware RT (Triangle-based) |
|---|---|---|
| Tracing method | Signed Distance Fields (SDF) | Traces directly to polygon geometry |
| GPU requirement | Any modern GPU | RTX / RDNA3 with dedicated RT cores |
| Reflection quality | Soft, blurred on curved/chrome surfaces | Sharp, accurate — supports transparent materials |
| Performance | Significantly lighter | Heavy — detailed geometry calculation |

---

### 3. Key Settings — Project Settings & Post Process Volume

**Project Settings → Engine → Rendering:**
- `Dynamic Global Illumination Method` → set to **Lumen**
- `Reflection Method` → set to **Lumen**
- `Support Hardware Ray Tracing` → enable only when switching to HW RT (requires engine restart)

**Post Process Volume (per-area fine-tuning):**
- `Lumen Global Illumination Quality` — scale 1–4; higher reduces noise at performance cost
- `Lumen Reflections Quality` — controls clarity of reflections on reflective materials
- `Ray Lighting Mode` — on HW RT, switch from `Surface Cache` (faster) to `Hit Lighting` (cinematic accuracy)

---

### 4. Notable Feature — Emissive Materials as Light Sources

One of Lumen's most impactful features: objects assigned an emissive material automatically function as light sources. They emit both direct light and contribute to indirect lighting (GI bounce) in surrounding areas — without requiring a manually placed light actor.

---

### 5. Known Limitations & Troubleshooting

| Issue | Cause | Solution |
|---|---|---|
| Foliage shadow loss at distance | Thin geometry (leaves) not captured correctly by Mesh Distance Fields | Import foliage as standard Static Mesh, not Nanite |
| Noisy virtual shadow maps (Rect Light) | VSM noise on large-area lights near surfaces | `r.Shadow.Virtual.SMRT.RayCountLocal 8` · `r.Shadow.Virtual.SMRT.SamplesPerRayLocal 8` |
| Interior GI blocked entirely | HDRI Dome mesh generating a Distance Field collision that stops bounce rays from entering the scene | Remove HDRI Dome actor; let Sky Atmosphere handle sky contribution |
| Dark interior patches on complex structures | Lumen defaults to max 12 Lumen Cards per object; dense interior geometry exceeds card budget | Simplify mesh, split into separate actors, or increase card count via project settings |

## Critical Analysis — Why the HDRI Dome Issue Does Not Apply to My Project

During the tutorial, William Faucher demonstrates an interior scene where Global Illumination completely fails due to an HDRI Dome blocking Lumen's ray calculations. I verified this does not affect my current Star Wars hangar project, for two distinct reasons:

**Reason 1 — Engine Version Difference (UE 5.0 EA vs UE 5.4)**

The issue was specific to Lumen's early implementation in UE 5.0 Early Access (2021), where the system relied heavily on global Mesh Distance Fields and lacked a mature sky/backdrop object filter. HDRI Dome meshes generated Distance Field collision, which Lumen incorrectly treated as solid geometry blocking outgoing GI rays.

In UE 5.4 (the version I am using), Epic introduced a **Lumen Sky Visibility Pass** that explicitly identifies `Unlit` materials and sky/backdrop actors and routes them through a separate rendering pass. The engine now bypasses Distance Field collision checks for objects flagged as infinite background, meaning HDRI Domes no longer interfere with interior GI calculations.

**Reason 2 — Render Pipeline Architecture Difference**

The tutorial's apartment scene uses an **occlusion-driven GI architecture**: light enters through narrow windows, so a single failed GI bounce from outside destroys the entire interior lighting. My hangar uses a **direct-dominant GI architecture**: large-volume direct sunlight enters freely, and internal lighting (panel lights, floor strips) operates independently via emissive or placed light actors. The system never needs to rely on a precarious single-bounce path from an exterior source.

## Key Terminology

| Term | Definition |
|---|---|
| Global Illumination (GI) | Simulation of how light bounces between surfaces in a scene |
| Lumen Scene | Lumen's internal low-resolution world representation used for light calculation |
| Surface Cache | Per-object cache of surface lighting data used for efficient bounce ray computation |
| Lumen Cards | Projection cards wrapping each object to capture and store GI data |
| Mesh Distance Field (MDF) | Signed distance field generated per mesh; used by Software RT for collision/tracing |
| Sky Light | Sky Atmosphere actor — interacts with Lumen to provide ambient outdoor light |
| Virtual Shadow Maps (VSM) | UE5's high-quality shadow system; used alongside Lumen |
