## Issues Encountered & Solutions

### Issue 1 — DLSS Warning in UE5 Viewport

**Error:**
```
DLSS is not supported due to Not Supported. Please see the various LogDLSS+ categories...
```

**Root cause:**
DLSS and RenderDoc are fundamentally incompatible. DLSS relies on a proprietary NVIDIA driver path that RenderDoc cannot intercept — both cannot be active simultaneously.

**Solution:**
When the confirmation dialog "DLSS incompatible with API capture tools" appeared → clicked **Yes** to temporarily disable DLSS. DLSS can be re-enabled after the RenderDoc session by disabling the plugin.

> **Note:** For workflows that require DLSS to remain active during frame analysis, **NVIDIA Nsight Graphics** is the appropriate alternative to RenderDoc.

---

### Issue 2 — Capture Succeeded in UE5 But API Showed as "None" in RenderDoc

**Root cause:**
UE5 defaults to DirectX 12. The version of RenderDoc in use has more stable support for D3D11 — DX12 captures were not being recognized.

**Solution:**
Edit → Project Settings → Platforms → Windows → **Default RHI** → changed from **DirectX 12** to **DirectX 11** → restarted UE5.

After switching, the API Inspector in RenderDoc changed from `None` to **D3D11 (Active)** and frame capture succeeded.

---

### Issue 3 — "Capture Frame(s) Immediately" Button Unclickable

**Root cause:**
Window focus was on RenderDoc, not UE5. RenderDoc can only capture when UE5 is the active foreground application.

**Solution:**
Click the UE5 viewport first → press **F12** to trigger capture. Alternatively: click UE5 viewport → Alt+Tab to RenderDoc → button becomes interactive.

## Event Browser — Analysis

Capturing the Starship scene in UE5 produced **11,124 EIDs (Event IDs)** — a complete recording of every GPU command issued within a single frame.

### Event Browser Structure

```
User-defined Capture
└── FRDGBuilder::Execute              ← full UE5 rendering pipeline (Render Dependency Graph)
    ├── LumenSceneLighting             ← Lumen global illumination
    ├── GBufferClear                   ← GBuffer reset per frame
    ├── BasePass                       ← renders all geometry + materials (primary pass)
    │   ├── Light_emissive_Inst SM_SmallLight ...
    │   ├── M_Metal_Burnished_Steel_Inst SM_SmallLight  9 instances
    │   │   └── DrawIndexedInstanced(804, 9)   ← 1 draw call = 1 mesh rendered
    │   └── ... (additional draw calls)
    └── CanvasBatchedElements          ← editor UI (gizmos, viewport grid, debug text)
        └── DrawIndexed(6)
```

### Key Terminology

| Term | Description |
| --- | --- |
| **EID** | Event ID — sequential number assigned to each GPU command within a frame |
| **Draw call** | A single GPU command to render one mesh/object. Higher count = heavier GPU load |
| **DrawIndexed(6)** | Renders 6 vertices = 2 triangles (a quad or UI element) |
| **DrawIndexedInstanced(804, 9)** | Renders a mesh with 804 indices, repeated 9 times via instancing |
| **FRDGBuilder::Execute** | UE5 Render Dependency Graph — orchestrates execution order of all render passes |
| **BasePass** | Primary render pass — writes geometry and material data for all 3D objects into the GBuffer |
| **GBuffer** | A set of textures storing per-pixel material data (albedo, normals, roughness, etc.) before lighting is evaluated |
| **CanvasBatchedElements** | Editor overlay elements — gizmos, viewport grid, debug text |
| **Lumen** | UE5's real-time global illumination and reflection system |

### Practical Usage as a Technical Artist

- **Check draw call count** → identify whether a scene is performance-heavy at a glance
- **Click a BasePass draw call** → inspect the mesh in Mesh Viewer, active textures in Texture Viewer
- **Find draw calls appearing hundreds of times** → flag as bottleneck candidates for optimization
- **Click a draw call → API Inspector** → review raw GPU commands in full detail (SetShader, SetTexture, etc.)

> **Key insight:** RenderDoc teaches how the GPU *thinks* — not from an artist's perspective (material appearance, lighting feel) but from the machine's perspective (draw call budget, pass order, which textures are active at each pipeline stage). This is the foundation for data-driven optimization conversations with engineers.
