## Chapter 04 — Running Your Shader

### Core Idea

A shader cannot run on its own — it requires a platform or framework to act as its host environment.

### Browser-Based Ecosystem Tools

| Tool | Function | Link |
|------|----------|------|
| **glslCanvas** | Render shaders via an HTML `<canvas>` tag | [GitHub](https://github.com/patriciogonzalezvivo/glslCanvas) |
| **glslViewer** | Run shaders via terminal / command line | [GitHub](https://github.com/patriciogonzalezvivo/glslViewer) |
| **glslEditor** | Interactive online shader editor | [editor.thebookofshaders.com](http://editor.thebookofshaders.com/) |
| **glslGallery** | Curate and showcase shaders as art pieces | [GitHub](https://github.com/patriciogonzalezvivo/glslGallery) |

### Framework Support

- **Three.js** (JavaScript/Web) — shaders defined in `<script>` tags with type `x-shader/x-fragment`
- **Processing** (Java-like, beginner-friendly) — shaders stored in `.frag` files inside the `data/` folder
- **openFrameworks** (C++) — similar to Processing; the `ofxShader` addon simplifies workflow

### 3 Standard Uniforms

```glsl
uniform vec2 u_resolution;  // screen size       → Unreal: ViewSize, TexCoord
uniform vec2 u_mouse;       // cursor position   → Unreal: cursor nodes
uniform float u_time;       // elapsed time      → Unreal: Time node
```

### Relevance to Unreal Engine

In Unreal, GLSL is not written directly — the engine uses the **Material Editor** (node-based, visual) or **HLSL** for manual shader code. However, the mathematical concepts and logic are **identical**. The Book of Shaders teaches a *way of thinking*, not platform-specific syntax.

## Chapter 05 — Shaping Functions

### Core Idea

> Every shader is essentially about manipulating values between **0.0 and 1.0**

Shaping functions are the primary tools for bending values within that range to produce the desired visual output.

### Essential Functions

#### 1. `pow()` — Exponentiation

```glsl
y = pow(x, 5.0); // produces a curved response
```

Try different exponents: `20.0`, `2.0`, `1.0`, `0.2`, `0.02` — each produces a distinct curve.
→ Unreal equivalent: **Power** node

#### 2. `step()` — Hard Threshold

```glsl
y = step(0.5, x);
// x < 0.5 → 0.0 (black)
// x > 0.5 → 1.0 (white)
```

Useful for masks, hard edges, and binary selection.
→ Unreal equivalent: **If** node

#### 3. `smoothstep()` — Smooth Transition

```glsl
y = smoothstep(0.2, 0.8, x);
// smoothly transitions from 0.0 to 1.0 between x=0.2 and x=0.8
```

The go-to function for any soft edge, material blend, or color transition.
→ Unreal equivalent: **Smoothstep** node, **Lerp** node

#### 4. `sin()` & `cos()` — Waves & Animation

```glsl
y = sin(x);           // base wave (range: -1 to 1)
y = sin(x + u_time);  // animated wave (moves over time)
```

**Key technique — Remap sin to 0–1 range:**

```glsl
y = sin(u_time) * 0.5 + 0.5;
// sin: -1 ~ 1  →  *0.5: -0.5 ~ 0.5  →  +0.5: 0.0 ~ 1.0
```

→ Unreal equivalent: **Sine → Multiply(0.5) → Add(0.5)**

**Common `sin()` variations:**

| Expression | Visual Effect |
|------------|---------------|
| `sin(x + u_time)` | Moving wave (animation) |
| `sin(x * PI)` | Increased frequency (tighter waves) |
| `sin(x) + 1.0` | Shifted up (range 0–2) |
| `sin(x) * 2.0` | Doubled amplitude |
| `abs(sin(x))` | Bouncing ball effect |
| `fract(sin(x))` | Chopped / repeating pattern |

### GLSL → Unreal Engine Reference Map

| GLSL Concept | Unreal Node |
|--------------|-------------|
| `u_time` | **Time** |
| `u_resolution` / UV | **TexCoord** |
| `sin(x)` | **Sine** |
| `sin * 0.5 + 0.5` | Sine → Multiply → Add |
| `smoothstep()` | **Smoothstep** |
| `mix()` / lerp | **Lerp** |
| `pow()` | **Power** |
| `abs()` | **Abs** |

## Lava Shader Analysis — M_LavaLearning ([2026-05-31](../daily/2026-05-31.md))

The node graph built previously turns out to already implement the core concepts from Chapter 05.

### Left Section — UV Animation

```
TexCoord → Add → Texture Sample (noise)
Time → Multiply(0.34, 0.12) → ↑
```

**Theory applied:** `sin(x + u_time)`

UV coordinates are offset over time using the Time node, giving the lava a flowing appearance. Two noise layers with different speeds `(0.34, 0.12)` and `(0.13, 0.26)` prevent the motion from looking uniform or mechanical.

### Middle Section — Glow Pulse

```
Time → Multiply → Sine → Multiply(0.5) → Add(0.5) → GlowIntensity
```

**Theory applied:** sin-to-0–1 remapping

- `Sine` outputs: –1 to 1
- `Multiply(0.5)` outputs: –0.5 to 0.5
- `Add(0.5)` outputs: **0.0 to 1.0** ✅

GlowIntensity pulses up and down smoothly — producing the glowing lava effect.

### Right Section — Color Blending

```
OrangeColor ──→ Lerp ──→ Base Color
YellowColor ──↗   ↑
              Alpha (from noise texture)
```

**Theory applied:** `smoothstep()` / `mix()`

The noise texture acts as an Alpha mask for blending between orange and yellow, creating a natural hot-cold variation across the lava surface.

### Flow Diagram

```
UV + Time ──→ [2× Noise Texture] ──→ Blend (Lerp)
                                           ↓
OrangeColor + YellowColor ──────→ Base Color Output

Time ──→ Sine ──→ Remap 0-1 ──→ GlowIntensity ──→ Emissive Output
```

## Key Takeaways

1. **Shaders need a host environment** — in Unreal, that host is the Material Editor
2. **Every shader is about controlling values between 0.0 and 1.0** — shaping functions are the primary tools
3. **`smoothstep` is the most-used function in shader development** — memorize it first
4. **`sin(u_time) * 0.5 + 0.5`** is an essential pattern for smooth oscillation animation
5. **The lava shader already used all these concepts** — Chapter 05 theory was applied in practice before it was studied formally
