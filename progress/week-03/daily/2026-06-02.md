## Experiment 1 — Sky Light Integration in an Existing Scene

### Objective
Apply Sky Light to an existing project that already uses multiple RectLights as the primary lighting backbone, and measure the visual and performance impact.

### Setup
- Reverted project settings from Hardware RT to **Software Ray Tracing**
- Enabled **Lumen** in Project Settings
- Captured baseline screenshot (no Sky Light), then added Sky Light and captured a second screenshot for comparison

### Key Observation During Setup
> Switching from Hardware RT to Software RT triggers a **full shader recompile**. In a scene of this complexity (176 actors, 10+ RectLights), this process takes significant time — a real-world workflow cost that must be factored into production pipelines.

---

### Performance Comparison

| State | FPS | Frame Time |
|---|---|---|
| **Before Sky Light** | 57.91 FPS | 17.27 ms |
| **After Sky Light** | 53.20 FPS | 18.80 ms |
| **Delta** | −4.71 FPS | +1.53 ms |

### Conclusion — Experiment 1

The visual change is **subtle, not dramatic** — and that is the correct outcome.

This scene uses a **direct-dominant GI architecture**: RectLights already function as the primary lighting backbone. Sky Light's role is to fill the gaps unreachable by direct lights. A dramatic change would have indicated a problem with the original lighting setup.

- Sky Light adds ambient fill to areas outside direct light reach ✅
- Visual change: subtle but technically valid ✅
- GPU cost: +1.53 ms — normal and acceptable ✅
- Confirms RectLight setup is functioning as intended ✅

## Experiment 2 — Software Ray Tracing vs Hardware Ray Tracing

### Objective
Compare Lumen's Software RT (SDF-based) against Hardware RT (dedicated RT Cores) on an RTX 5060 Ti 16GB, using the same hangar scene.

### Method
1. Opened `stat unit` in the viewport console → recorded GPU time values
2. Opened GPU Visualizer (`Ctrl+Shift+,`) → captured pass breakdown
3. Repeated both steps after switching to Hardware Ray Tracing

---

### Part 1 — Performance Overview (Stat Unit Comparison)

| Metric | Software RT (SDF) | Hardware RT (RT Cores) | Change |
|---|---|---|---|
| **Frame Rate** | 60.11 FPS | 48.00 FPS | −12.11 FPS |
| **Total GPU Time** | 16.00 ms | 19.96 ms | +3.96 ms |
| **RHIT Thread** | 0.38 ms | 6.63 ms | +6.25 ms |
| **Bottleneck** | GPU Bound | GPU Bound | No change |

### Part 2 — Deep Dive: LumenSceneLighting Pass Analysis

**Software RT (2.28 ms total)**
- Heavy reliance on `Radiosity` (1.40 ms) driven by `DistanceFieldTracing` (0.49 ms)
- Lighter hardware setup; bounce light processed mathematically via shaders
- RHIT overhead: negligible (0.38 ms)

**Hardware RT (1.70 ms total)**
- Dedicated RT Core usage confirmed via `LumenDirectLightingHardwareRayTracingRGS` (0.90 ms)
- `Radiosity` drops to 0.37 ms — a direct result of hardware acceleration
- Internal Lumen calculations are faster (1.70 ms vs 2.28 ms)
- However, BVH traversal and RHIT introduce significant global overhead — driven by the scene's large number of instanced Stormtrooper meshes

> **Key insight:** Hardware RT makes Lumen's internal math faster, but the RHIT communication cost with RT Cores creates global overhead that can outweigh internal gains — especially in scenes with massive instanced meshes.

### Part 3 — Visual Quality Analysis

**Software RT**
- Floor reflections appear slightly blurry on distant objects → SDF geometry simplification loses fine detail
- Metallic wall arches show sharp light-to-shadow transitions, with occasional specular noise on camera movement
- Overall result is clean but lacks geometric precision in reflective surfaces

**Hardware RT**
- Floor reflections are sharp and geometrically accurate — Stormtrooper armor detail visible in floor reflections
- Contact shadows (between boots and floor) are tight and natural, eliminating the "floating" character artifact
- Specular highlights on the metallic wall arch blend smoothly — no banding or sharp transitions
- Bounce light distributes more evenly across the scene

---

### Part 4 — RTX 5060 Ti 16GB Assessment

| Method | RTX 5060 Ti Behavior |
|---|---|
| Software RT | Runs efficiently via Compute Shaders; RHIT overhead minimal |
| Hardware RT | Fully utilizes dedicated RT Cores for acceleration; overhead increases with instanced mesh count |

The RTX 5060 Ti 16GB supports both methods natively. The 16GB VRAM headroom is a meaningful advantage in complex scenes — no texture streaming pressure observed during testing.

---

### Conclusion — Experiment 2

Software RT is significantly lighter overall because it avoids hardware communication overhead, making it the preferred choice for performance-critical scenarios or scenes heavy with instanced actors.

Hardware RT delivers superior visual quality — particularly in reflections, contact shadows, and GI bounce distribution — but introduces global overhead that scales with scene complexity (especially instanced mesh count). Internal Lumen pass performance improves, but total frame cost increases.

**Practical takeaway:** For this scene, Software RT is the better runtime choice until the instanced mesh overhead of Hardware RT can be optimized. Hardware RT's quality advantage is real and visible, but not yet cost-effective at 48 FPS on this geometry load.
