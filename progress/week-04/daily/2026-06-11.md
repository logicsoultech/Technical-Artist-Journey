## 📖 Theory: What Is Texture Compression and Why Does It Matter?

Texture compression is the process of reducing the memory footprint of texture data stored on the GPU. Uncompressed textures are enormous — a single 2K RGBA texture at 32-bit takes up 16 MB of VRAM. In a game with hundreds of textures, this quickly exhausts memory budgets and degrades performance.

Compression formats like DXT (also called S3TC / BCn) work by dividing the texture image into 4×4 pixel blocks and approximating color values within each block using a reduced data representation. This lossy compression preserves visual quality acceptably while achieving dramatic memory savings.

**Why this matters for a Technical Artist:**

- TAs are responsible for defining and enforcing texture compression standards across the art team
- Incorrect compression settings (e.g. leaving sRGB on a data map) is one of the most common and hardest-to-diagnose bugs in a material pipeline
- Understanding compression tradeoffs allows TAs to optimize VRAM budgets without sacrificing visual quality
- These settings connect directly to multi-platform support — mobile, console, and PC have different compression requirements

## 🗺️ Concept Map: Texture Compression Types in UE4/UE5

### Rule #1 — Power of Two (PoT)

Imported textures **must** have dimensions that are a power of two: 64, 128, 256, 512, 1024, 2048, 4096. Non-PoT textures cannot be compressed by the DXT algorithm and will be stored uncompressed, consuming far more VRAM than intended. This is the single most common texture import mistake.

> ✅ Valid: 512×512, 1024×2048, 256×1024
> ❌ Invalid: 600×800, 1000×1000, 512×300

Textures do not need to be *square* — only each individual dimension must be PoT.

---

### 1. Default — DXT1 / DXT5 (BC1 / BC3)

The general-purpose compression setting, used for **Albedo / Base Color** textures.

| Condition | Format Used | Compression Ratio |
|---|---|---|
| No alpha channel | DXT1 (BC1) | ~6:1 (smallest) |
| Has alpha channel | DXT5 (BC3) | ~4:1 |

- **DXT1** is the most efficient format available — it should be the default target whenever alpha is not needed
- **DXT5** adds a compressed 8-bit interpolated alpha channel. The alpha uses 2 explicit values and interpolates between them, making it well-suited for soft gradients
- Adding an alpha channel to a DXT5 texture consumes as much memory as the other three channels combined — this is a meaningful cost to consider before packing alpha
- DXT compression creates subtle block artifacts on very smooth gradients (visible as faint 4×4 pixel squares) because the algorithm approximates within 4×4 blocks

**Practical rule:** If your albedo does not require transparency, ensure it has no alpha channel so UE automatically selects DXT1.

---

### 2. Normalmap — DXT5 / BC5

Dedicated compression for **Normal Maps**.

- On DX11+, UE uses **BC5** (also called ATI2 or 3Dc), which stores only the R and G channels (X and Y normal vector components)
- The Z (blue) channel is mathematically reconstructed in the material graph: `Z = sqrt(1 - X² - Y²)`
- BC5 is significantly more accurate than DXT5 for normals because DXT5's 4×4 block compression causes visible smearing on fine normal details
- BC5 **discards the blue and alpha channels** of the source texture — any data stored there will be lost
- The default base color of a flat normal map is `#8080FF` — if BC5 is applied, the blue channel is discarded but the engine reconstructs it, so flat surfaces remain correct

**When to use DXT5 on a normal map:** Only when you need to pack additional data (e.g. roughness) into the alpha channel of the normal map. Accepted tradeoff: slightly lower normal precision.

---

### 3. Masks (no sRGB)

Used for **Roughness, Metallic, AO, Opacity Masks**, and any packed data texture (ORM).

- Functionally identical to Default in terms of compression algorithm (DXT1 or DXT5 depending on alpha)
- The critical difference: **sRGB is automatically disabled**
- Data maps carry linear mathematical values — they must not undergo gamma correction
- If sRGB is left ON for a Roughness map, the engine applies gamma correction (~2.2 power curve) to linear data, distorting all roughness values. The surface will appear wrong across all lighting conditions — subtly wrong under some lights, severely wrong under others

**The most common pipeline bug:** An artist imports a roughness or metallic map without changing the compression setting, leaving sRGB ON. The result is always incorrect PBR behavior. This is hard to catch without systematically checking each texture's compression setting.

---

### 4. Grayscale

Used for single-channel grayscale data: **Height maps, Cavity maps, simple masks**.

- Stores the texture as a single 8-bit channel (R8)
- More memory-efficient than packing a grayscale value into all three channels of a Default-compressed texture
- sRGB is available but if enabled, the format switches to an uncompressed 32-bit B8G8R8A8, negating the memory savings — so for data maps, leave sRGB OFF

---

### 5. Address Mode — Shared: Wrap

Every TextureSampler node in the material graph has an Address Mode setting, which controls what happens when UV coordinates go outside the 0–1 range.

| Mode | Behavior |
|---|---|
| **Wrap** | UV repeats (tiles) — used for seamless tileable textures |
| **Clamp** | UV stops at the edge — no repetition |
| **Mirror** | UV mirrors and repeats |

For AmbientCG-style seamless tileable textures, the Address Mode must be set to **Shared: Wrap**. Setting it to Clamp on a tiling texture will cause a visible edge seam on the mesh wherever UV coordinates exceed 1.

## 🔬 Compression Efficiency Summary

| Format | Channels Stored | Compression Ratio | Best For |
|---|---|---|---|
| DXT1 (BC1) | RGB (no alpha) | ~6:1 | Albedo without transparency |
| DXT5 (BC3) | RGBA | ~4:1 | Albedo with alpha, normal + data packing |
| BC5 | RG only | ~2:1 but high accuracy | Normal maps |
| BC4 | R only | ~2:1 | Single-channel alpha/grayscale |
| Uncompressed | RGBA full | 1:1 | UI (when precision critical) |

## 📝 Technical Artist Notes for UE5.4

**Alpha Channel Cost**
Before adding an alpha channel to any texture, confirm it is actually needed. A DXT5 texture uses 1.5× the memory of DXT1. Across 50 albedo textures in a scene, unnecessary alpha channels can add tens of megabytes of VRAM waste.

**The sRGB Bug — Quick Diagnosis**
If a material looks too rough everywhere, too smooth everywhere, or has inconsistent behavior under different light colors → check sRGB settings on Roughness and Metallic maps first. This is the correct first diagnostic step before investigating material nodes.

**BC5 and Alpha Channel**
If a Normal map uses BC5 (Normalmap setting), the alpha channel is discarded. If you need to pack roughness or a mask into the alpha of a normal map, switch to Default (DXT5) compression and accept the slight quality tradeoff on normal precision.

**Non-PoT Textures in UE5**
UE5 will import non-PoT textures without an error, but they will be stored uncompressed. This is a silent memory issue — the engine won't warn you during normal workflows. TAs should include a PoT check in the asset validation pipeline or import checklist.

**ORM Packing and Compression**
When using a packed ORM texture (AO in R, Roughness in G, Metallic in B), the correct compression setting is **Masks** with **sRGB OFF**. All three channels are linear data. Using Default with sRGB ON will corrupt all three values simultaneously.

**Texture Budget Guidelines (Revisited)**

| Asset Type | Recommended Resolution |
|---|---|
| Background / far distance | 512–1K |
| General environment props | 2K |
| Hero / foreground assets | 4K |
| UI elements | Uncompressed or UserInterface2D |

## 💡 Insights & New Understanding

- Texture compression is not a single setting — it is a **system of decisions** per texture type. Treating it as "just click import" is the root of most texture-related pipeline bugs.
- The DXT1 vs DXT5 decision is not about quality — it is entirely about whether an alpha channel exists. Removing unnecessary alpha channels is a zero-effort optimization with real VRAM savings.
- BC5 is strictly better than DXT5 for normal maps *unless* you need the alpha channel for data packing. Knowing when to make that tradeoff is a TA judgment call.
- sRGB is a color space for human perception, not for data. Data maps (roughness, metallic, AO, normals) are mathematical values and must bypass sRGB correction entirely.
- Understanding these compression formats at this level enables systematic diagnosis of material bugs — instead of trial and error, a TA can reason from the data to the likely failure point.
